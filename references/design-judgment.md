# 加字段还是加对象？设计判定手册

> 学习资料。回答高频问题：新功能来了，"框框加个字段"什么时候可以，什么时候会埋雷。
> 配套阅读：[design-walkthrough.md](design-walkthrough.md)（整体导读）、`msp/spec.md` §2/§8（对象与操作）。

## 0. 一句话 + 三个杀手测试

**字段描述"是什么"，对象讲述"发生了什么"。**
一个新东西如果只会被问"它是什么/值多少"，就是字段；一旦会被问"它什么时候变的、谁改的、
能不能回放、为什么是这个数"，它就是对象/事件/账本。

三个杀手测试（任一命中 → 不能只加字段）：

1. **删表重建测试**：把放它的那张表删了，这个值还能从别处重建吗？不能 → 它是历史/权威事实，不是字段。
2. **审计员测试**：一年后有人问"这笔钱/这个权益为什么是这个数"，你能指着一张**不再变化**的记录回答吗？
   不能 → 你的字段会变或被覆盖，错了。
3. **重放测试**：同一条事件重试/重放两次，这个字段会翻倍或互相覆盖吗？会 → 需要幂等键/追加语义。

## 1. 六问判定法

| # | 问题 | 字段 OK 的答案 | 必须升级的信号 |
| --- | --- | --- | --- |
| 1 | 有几个值？会变几次？ | 1:1，几乎不变 | 1:N、N:M、随时间增长的历史 |
| 2 | 有自己的生命周期吗？ | 无，只是描述 | 有出生/变化/终结，或被单独引用/争议/审计 |
| 3 | 参与钱/权等式吗？ | 不参与 | 金额、余额、权益、退款、判权 |
| 4 | 谁能改、何时能改？ | 随时改都无害 | 只有特定操作+特定状态能改，且要留痕 |
| 5 | 并发/重试/重放安全吗？ | 无所谓 | 会重复写、互相覆盖 |
| 6 | 必须定格吗？ | 不需要 | 必须定格在某个时刻（快照） |

## 2. 三种归宿

- **属性（field）**：静态描述、1:1、不参与钱权。例：`nickname`、`remark`、报价的 `trial_days`。
- **快照（snapshot field）**：仍是字段，但 copy-on-create，之后不随源变化。例：订单价格/标题、发票税率、发货地址。
- **对象/事件（entity + 状态机 + 事件 + 不变量）**：有生命周期、1:N、参与钱权、需要审计重放。
  例：退款工单、Dispute、权益、账本条目。

## 3. 正反例子

### A. `trial_days` 字段 OK；"试用状态"字段不行

- 报价上的 `trial_days=7` 是静态属性 → 字段。
- 想在订单上加 `is_trial` 表达"用户正在试用" → 错：试用有开始、到期、转正/过期两个出口、还影响判权。
  正确姿势 = Membership `trialing` 状态 + `subscription.trial_started` 事件 + OP-T1/T2 + T-41/42。

### B. 退款金额单字段 OK 一次；第二次退款就爆

- `Refund.amount` 一笔一值 → 字段。
- 给订单加 `refunded_amount` 想支持部分退款 → 第二笔覆盖第一笔、历史丢失、可能超退。
  正确姿势 = `Refund.lines[]` + 多工单 + INV-28（Σ成功退款 ≤ paid）+ T-39/40。

### C. 税率：引用是雷，快照是对

- 发票 `tax_rate` 指向 Product 当前税率 → 目录改价污染历史发票。
  正确姿势 = 下单时复制 `TaxSnapshot`（INV-2，T-47）。

### D. 幂等键：单列字段会"顶掉"合法数据

- `points_ledger.event_id UNIQUE` 单列 → 一单多项的第二条被顶掉（L-010）。
  正确姿势 = `(event_id, ref_id)` 复合唯一（INV-15，T-28）。

### E. 余额字段可以存在，但只能是"物化缓存"

- `balance` 是合法字段，前提是它永远由账本推导、可删掉重建（ledger.md 策略 B）。
  API 直接 UPDATE balance = 反模式。

### F. `meta` 的晋升路径

- 塞进 `meta` 的键值对，一旦开始被 `if` 判断、参与资金/判权，就必须升格为正式字段（甚至对象）。
  纪律：**`meta` 里不做决策**。

## 4. 反模式速查

- 把生命周期压成一个枚举字段（只有状态，没有历史与原因）；
- 把 1:N 压成 JSON 数组参与资金运算，且允许事后改写；
- 用字段替代账本（直接 UPDATE 余额/库存）；
- 引用源对象代替快照（改价污染历史）；
- 起"xx_at/xx_by/xx_count"的名字却不落历史，假装能审计。

## 5. 决策顺序

1. 它有几个、变几次？（>1 或持续增长 → 直接归入"对象/事件"）
2. 它有自己的故事线或被单独引用吗？（是 → 对象 + 状态机 + 事件）
3. 它进钱权等式或并发幂等吗？（是 → 追加/幂等键 + 不变量 + 测试向量）
4. 它必须定格吗？（是 → 快照字段；否则普通字段；塞不进就进 `meta`，但**禁止做决策**）

## 6. 与协议五层的关系

MSP 由五层组成：对象 / 操作 / 不变量 / 事件 / 符合性。加字段只动"对象"层；
一旦答案跨进"操作（谁能改）/ 不变量（不能违反什么）/ 事件（要留痕重放）"任何一层，
就说明字段不够——这个映射本身就是判定表。
