# 选型访谈与方案档位（solution tiers）

> 执行本技能的第一步必读。访谈规则（三问 / 保守假设 / 理由要求）的**唯一权威**见
> agent-skills-index 的 `conventions/solution-interview.md`；本文只保留本技能的档位表。

## 1. 访谈（一次问清，≤3 个问题）

| # | 问题 | 取值（示例） | 用途 |
| --- | --- | --- | --- |
| 1 | **目的**是什么 | 验证想法 / 自用经营 / 商业产品 / 多产品基础设施 | 定档位主轴 |
| 2 | **规模**多大 | 日订单量级（<10 / <100 / <1000 / ≥1000）、用户量级、团队（solo / 小团队 / 多产品）、预算 | 定档位落点 |
| 3 | **硬约束**有哪些 | 执照与 ICP 备案有无、技术栈、地区合规、已有系统要改造 | 修正档位取值 |

规则见 `conventions/solution-interview.md`（未回答项按最保守假设并在产出标注"未确认"）。

## 2. 档位矩阵（目的 × 规模）

| 档位 | 目的 | 规模 | 典型方案 | 核心理由 |
| --- | --- | --- | --- | --- |
| **L0 最小验证** | 验证想法（可能没人付钱） | <10 单/日，solo，零预算 | `personal_qr` + 截图审核或金额指纹 + `single_host_compose` + 仅 Core 等级 | 用最少建设拿到"是否有人愿意付钱"的信号，不过度工程 |
| **L1 独立经营** | 自用小站 / 熟人圈 | <100 单/日，solo，无执照 | `personal_qr` + `hybrid`（指纹快车道 + 截图兜底）或 `aggregation_webhook`；Core+Subscriptions（+Points 按需） | 零执照可上线；证据强度与兜底配齐；人工可消化单量 |
| **L2 商业产品** | 陌生人付费经营 | <1000 单/日，有执照 + 备案 | `official_gateway` + `+dunning` + `tax_snapshot`（`+fx_snapshot` 按需）+ Disputes 等级 | 回调消除身份盲与伪造；自动化支撑人力上限；合规（发票/争议）跟上 |
| **L3 可复用基础设施** | 多产品复用 | 任意规模但有明确增长预期 | L2 全量 + 内核闭环 + 插件注入 + **独立身份层**（identity-system-builder）+ 事件基础设施 | 认证/权益分离；扩展只加不改；跨产品共享代码（L-001），不共享服务 |

各档位的**分支取值全集**见 SKILL.md 第一步的分支表；档位只决定"取哪几个分支的哪个值"，
不改变分支表本身。收款方式、到账确认、退款深度、争议、发票、多币种等分支随档位升降：

- L0 → 全部取最小实现（`whole_order`、`none`、`single_currency`）；
- L1 → 到账确认升到 `hybrid` 或 `aggregation_webhook`，其余仍最小；
- L2 → 官方直连 + `+dunning` + `tax_snapshot`，按单量开 Disputes；
- L3 → 在 L2 之上补插件内核与身份层，Invoicing/MultiCurrency 按产品需求开。

## 3. 换档触发器（什么时候必须升档 / 允许降档）

**升档（任一命中即升）：**

- 日订单接近当前档位上限（80% 水位）；
- 出现一次伪造凭证 / 撞码 / 双花 / 资损事件 → 立即升档（先止血，再评估永久档位）；
- 人工审核量超过单人日容量 → L1 升 L2；
- 第二个产品要用同一套账号 → 至少把身份层独立出来（L3 的认证部分）；
- 拿到执照 + ICP 备案 → 可评估升 L2。

**降档（避免过度建设）：**

- 目的只是"验证想法" → 永不预建 L2/L3 能力，宁可 L0 跑通再升；
- 已建能力连续一个月无真实流量 → 按 maintenance.md §5 降级或退役。

## 4. 理由模板（写进产出的分支决策章节）

```text
档位：L1
依据：目的=自用小站；规模=<100 单/日，solo；硬约束=无执照
理由：零执照可上线；hybrid 保证监听挂掉仍有截图兜底；人工可消化单量
为什么不是 L0：已有真实付费预期，截图审核的证据强度与对账必须配齐
为什么不是 L2：无执照 + 备案，官方直连不可行；单量未到人工上限
未确认假设：（无）
```
