# 交付计划模板（阶段 + 验收标准）

原则：**每个阶段以真实数据库端到端可用性收尾**，验收命令写进文档并实际跑过；"编译通过"不算完成。

## Phase 0 骨架

交付：仓库结构（含 `extensions/` 目录与扩展注册表骨架）、后端骨架（配置/连接池/自动迁移/健康检查/优雅退出）、前端脚手架、本地 compose、完整数据库 DDL。

验收：

```bash
docker compose up -d postgres
go run ./cmd/api          # 启动即迁移
curl 127.0.0.1:8080/healthz
# 数据库表齐全，schema_migrations 有记录
```

## Phase 1 成交主线

交付：独立账号（注册/登录/JWT）、商品目录、订单状态机、支付（金额指纹或网关）、到账匹配、outbox 履约（发权益）、我的权益接口。

验收（端到端冒烟脚本，必须真实跑通）：

```
注册 → 看商品 → 下单 → 签发支付 → 模拟到账 → 订单 fulfilled → 权益 +1
```

## Phase 2 业务扩展（按业务范围裁剪）

交付：内容门控、礼物（消耗/收藏 + 榜单）、积分（订阅赠送 + 充值 + 兑换订单）、收货地址 + 周边下单 + 发货单。

验收：每条资金链路账实相符，例如：

```
买会员 → 解锁会员内容 + 订阅赠送积分
买积分包 → 余额 = 面值 + 赠送
积分兑换 → 扣积分 + 礼物入库
周边下单 → 生成发货单
```

## Phase 3 运营与风控

交付：退款工单（申请 → 审核 → 一站式冲销）、续费提醒（7/3/1 天 + 过期清理）、管理端（统计/订单/退款/发货/内容管理）、行为事件。

验收：

```
申请退款 → 管理员通过 → 订单 refunded + 权益回收 + 积分/礼物扣回（不足则转人工）
把权益到期时间改到 20 小时后 → 提醒 worker 生成 renewal_d1 站内通知
管理端统计返回真实数据
```

## Phase 4 前端与部署

交付：用户端页面（首页/创作者主页/商品/订单支付/内容/个人中心）、管理后台页面、Dockerfile、生产 compose、入口网关配置、部署脚本、部署手册。

验收：

```
前端生产构建通过（含管理页路由）
页面渲染 200；/api 同源反代返回真实 JSON
部署脚本一条命令完成：本机构建 → 上传 → 服务器重建 → 容器内健康检查
HTTPS 域名可访问；同机其他业务站点未受影响
```

## 每阶段的固定动作

1. 写/更新设计文档（数据表、事件流、边界决策）；
2. 实现 + 单元/冒烟测试；
3. 跑真实验收并把输出贴进文档；
4. 记录踩坑（bug-log / 决策记录）。

## 反模式

- 阶段没有验收标准，或标准是"代码写完了"；
- 把多个阶段混在一个大提交里，出问题无法二分；
- 只测 happy path，不做"重复投递 / 重复点击 / 重复退款"的幂等验证。
