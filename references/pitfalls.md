# 真实踩坑清单（按分支挑选进产出技能）

以下每一条都是实际项目中发生过或被验证过的坑。生成构建技能时，至少覆盖**支付**与**幂等**两类。

## 支付与对账

1. **跨系统撞码**：两个系统监听同一收款账户时，同一金额会被两边同时匹配 → 双花。必须使用不同账户/渠道，或分区金额后缀空间（并写进配置约定）。
2. **`ON CONFLICT` 与部分唯一索引**：冲突目标必须重复索引谓词——`on conflict (event_id, ref_id) where event_id is not null do nothing`；缺谓词报 `SQLSTATE 42P10`。这条错误只在运行时出现，务必有真实数据库的集成测试兜住。
3. **固定金额被"消费"**：订阅续费要复用同一数字，匹配成功后必须保持 `active`（只解绑订单/支付单）；一旦置成 `consumed`，续费就再也匹配不上。
4. **取消/超时不释放占用**：金额空间随时间枯竭，用户下单会看到"金额繁忙"。
5. **改价僵尸码**：报价涨价后旧固定金额仍活跃 → 用 `price_cents` 快照识别并作废。
6. **只按整数元匹配**：冲突概率极高，必须加唯一分位。
7. **监听端不可信**：内部回调接口也要 HMAC 验签 + 时间窗 + nonce 防重放。
8. **漏单**：监听端会挂机，必须有用户自助举证 + 人工补单，且补单走与自动匹配相同的履约路径。
9. **对账缺位**：`unmatched` 通知与 `failed` 事件必须有人看；不做每日对账，问题会在几周后以"用户投诉"的形式爆出来。

## 幂等与一致性

10. **一单多项的幂等键**：`event_id` 单列唯一会互相顶掉 → 用 `(event_id, ref_id)`（积分）或 `(event_id, product_id)`（礼物）。
11. **余额直接 UPDATE**：必须"流水 + 余额快照"同事务写入；只改余额无法审计、无法对账、并发下会错。
12. **outbox 处理器不幂等**：worker 在失败时会重放整个事件；任何"先查后写"的处理器都要有唯一约束兜底。
13. **退款只改状态**：必须回收权益/积分/礼物；回收不满足（已送出/已花掉）→ 转人工，宁可不退。
14. **`failed` 事件的终态策略**：outbox 的 `failed` 若仍被 worker 领取，会无限重试。要么明确"无限退避重试"（可接受，但要告警），要么定死信转人工策略并写进文档。
15. **订单状态机缺少条件更新**：`update ... where status='pending'` 影响行数为 0 时不能继续履约，否则会重复发放。

## 业务规则

16. **权益续期丢天数**：提前续费必须在 `max(到期时间, now())` 上顺延；永久权益不能被订阅覆盖成有期限。
17. **收藏型礼物超卖**：限量计数与购买必须同事务 + `FOR UPDATE`。
18. **周边绕过地址校验**：周边下单必须校验"地址属于本人"，并在发货单里存**地址快照**（防改址争议）。
19. **弱口令管理员**：管理员账号必须强密码；管理员开通（`admin_users`）要有固定流程，不要手滑留下测试账号。

## 工程与部署

20. **前端 rewrites 构建期固化**：Next 的 `rewrites()` 在 `next build` 时求值，`INTERNAL_API_URL` 必须在构建期注入；运行期改环境变量无效。
21. **私有多模块的构建凭据**：容器内 `go build` 拉私有模块需要凭据 → 用 BuildKit secret 挂载（不进镜像层/缓存），或改为"本机构建二进制再上传"；凭据单独放服务器配置文件（600）或 CI Secret。
22. **私有模块校验值**：离线构造的模块 zip 与真实代理的 `h1:` 校验值可能不一致；以 CI 实测下载为准。
23. **构建网络**：服务器/构建机在国内时，Go 公共模块用 `GOPROXY=https://goproxy.cn,direct`；Docker Hub 不通时本地已有镜像要复用（`docker` driver builder 而非独立 multiarch builder）。
24. **Caddy 配置不热加载**：`admin off` 时改 Caddyfile 必须重启容器（`admin api` 开着才能 reload）；改完记得验证其他站点未受影响。
25. **证书与 DNS 顺序**：先有 DNS A 记录再签发证书；未解析期间 Caddy 会持续报错重试，但**不影响**其他站点。
26. **Docker 网络别名撞车**：多个 compose 项目接入同一网络时，服务名（`web`/`api`）会成为别名并互相覆盖 DNS → 共享网关场景只暴露带唯一别名的那一个容器（如 `fan-web`）。
27. **凭据进 git**：`git add -A` 会把仓库目录里的凭据文件一起提交。凭据文件必须在创建的第一时间写进 `.gitignore`，并在提交前用 `git show --stat` 复核。
28. **健康检查打错目标**：同机多站点时 `curl 127.0.0.1/healthz` 命中的是共享网关后面的别的服务 → 用 `docker compose exec <svc> wget -qO- http://127.0.0.1:<port>/healthz`。
29. **macOS tar 的扩展属性噪音**：`tar` 上传时加 `--no-mac-metadata` 或忽略 `LIBARCHIVE.xattr` 警告，避免刷屏掩盖真正错误。
30. **bash `set -e` 与 `[ ... ] && cmd`**：条件为假时整行返回非零，脚本会**静默退出**。用 `if` 语句代替。
31. **事件重试重复顺延权益**：续期 Upsert 无条件"到期时间 + 周期"，outbox 重试同一条 `order.paid` 会再次顺延；必须按 `(principal, product, source)` 幂等（INV-26）。
32. **退续费单退不到权益 / 退原始单端掉后续期**：续期不更新来源时，退款按来源回收必然双向错账；权益要按"订单贡献段"建模（OP-R2 ①）。
33. **数量不折算**：积分包/订阅按 quantity 收钱、只发一份；履约必须按 `q` 折算或下单时拒绝 q>1（OP-F1）。
34. **退款不取消发货单**：退钱后发货单仍 pending，可被继续发货——退款事务必须作废未发货单（OP-R2 ⑤）。
35. **超时不关单、金额占用不释放**：过期订单永远 pending、随机金额占用永远 active → 金额空间枯竭；必须有超时关单任务（OP-O5）。
36. **指纹尾数计入退款金额**：`paid_amount_cents` 存含尾数金额，退款按它计算每单多退分币；退款金额必须用应付金额（INV-20）。
37. **fixed 金额并发重绑定**：两张 pending 单共享一个金额码，到账按时间取最新单，老单被静默搁置；金额码必须租约独占（INV-27）。
38. **复合幂等键里 ref 为 NULL 不去重**：PostgreSQL 默认 NULL 互不冲突，`(event_id, NULL)` 重复插入会重复入账；事件驱动条目 ref 必须非空或 `NULLS NOT DISTINCT`（INV-15）。
39. **窗口边缘把"上报晚到"误判成"未支付"**：支付发生时刻在窗口内、监听上报晚到几秒就被 unmatched，用户被迫走人工补单；判定应以 `paid_at` 为准并给 `report_grace`（OP-P2，T-38）。
40. **接网关回调只验签就置 paid**：还必须验"回调金额 = 订单应付"（INV-20）与"付款人身份 = 订单用户"（openid），否则串单/代付会错绑用户。
41. **部分退款没有行级分摊与总额上限**：退一半时不知道回收哪一半权益段；没有 Σ ≤ paid 会重复退款。用 `Refund.lines` 按行回收 + INV-28。
42. **试用转正另开旁路 / 补差直接改权益时长**：转正必须复用普通订单履约；proration 补差必须走订单/账本，否则账本不可重建（OP-T2/OP-M1）。
43. **争议整行冻结权益**：冻结"更早订单+本单续期"合成的权益会误伤合法时段；必须按段冻结（INV-29）。
44. **改税率影响已开票 / 红冲直接改原票**：发票必须随订单快照税率；红冲是新增负向发票（OP-I1/I2）。
45. **跨币种用实时汇率重算退款**：对账永远对不平；必须用不可变 fx_snapshot 并按订单原币退款（INV-30）。
