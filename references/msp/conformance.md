# MSP 符合性判定（Conformance）

> 目的：把"系统是否可用"从主观判断变成**可执行、可留证的检查**。

## 1. 符合性等级（声明实现范围）

| 等级 | 覆盖 | 判定 |
| --- | --- | --- |
| **Core** | 目录、订单、支付、权益（含退款申请与冲销） | 必选，全部 MUST 必须通过 |
| **Subscriptions** | 订阅周期、续期单调、到期实时性、续费提醒 | 在 Core 基础上追加 |
| **Points** | 账本、余额安全、订阅赠送、充值、积分兑换 | 在 Core 基础上追加 |
| **Gifts** | 消耗/收藏型、限量、赠送、榜单 | 在 Core 基础上追加 |
| **Physical** | 地址、下单地址校验、发货单、发货 | 在 Core 基础上追加 |
| **Disputes** | 拒付/争议状态机、权益冻结与追索 | 在 Core 基础上追加 |
| **Invoicing** | 发票开具、税率快照、红冲 | 在 Core 基础上追加 |
| **MultiCurrency** | 汇率快照、跨币种结算与退款 | 在 Core 基础上追加 |

实现必须**显式声明**支持哪些等级；只考核声明范围内的规则。

## 2. MUST 清单（按主题，全部可勾选）

> 另有一份跨等级的设计判据清单（§3），与 MUST 清单同样必检、不可豁免。

**资金与订单**

- [ ] INV-1 金额整数：抽查数据库与接口，无浮点金额
- [ ] INV-2 订单快照：改价后旧订单金额不变
- [ ] INV-4/5 状态机封闭 + 条件迁移：非法迁移被拒绝且无副作用
- [ ] INV-6/7 支付唯一写入口 + 通知幂等：伪造请求被拒绝；重复上报不重复履约
- [ ] INV-8 金额占用唯一与及时释放：并发下单不产生重复活跃金额；超时关单后占用释放
- [ ] INV-20 金额一致性：支付金额等于订单应付；退款金额 = 应付（不含指纹尾数）
- [ ] OP-O4 取消释放：取消后金额占用被释放
- [ ] OP-O5 超时关单：过期订单转 closed，释放占用并作废支付单
- [ ] OP-R1/R2 退款：重复申请只有一个工单；通过即完成全部回退
- [ ] INV-16/17 退款完整性：礼物已送/积分已花时退款被拒并转人工；权益按段回收
- [ ] INV-27 结算码租约独占：任一金额码至多绑定一张未终结支付单
- [ ] INV-28 退款上限：多笔部分退款 Σ ≤ paid；按行回收（T-39/T-40）
- [ ] INV-31 支付意图并发上限：连点只产生一个支付单或复用；跨订单超上限拒绝且无副作用（T-55）
- [ ] INV-32 撞码限速与告警：签发失败退避 + 告警，高频失败熔断（T-56，personal_qr）
- [ ] 截图凭证唯一绑定：`(channel, transaction_no)` 唯一；重复上传返回 `duplicate`（T-52，截图/混合策略）
- [ ] 审核门禁：OCR 歧义 / 金额不符 / 时间出窗一律 `pending_review`，不得自动履约（T-53）

**权益与订阅**

- [ ] INV-3 单一判权源：删除订单数据后权益判定仍正确（只依赖权益）
- [ ] INV-9 续期单调：提前续费不丢天数；永久权益不被覆盖
- [ ] INV-26 发放/续期按 source 幂等：同一 `order.paid` 重放不再次顺延
- [ ] 试用：`trialing → expired` 实时生效；转正不丢剩余试用（T-41/T-42）
- [ ] proration：`changeOffer` 三种行为，补差走订单/账本（T-43）
- [ ] INV-10 实时到期：把到期时间改为过去后，下一次访问立即被拒
- [ ] OP-E1 `checkAccess` 覆盖 product/members 两种门控语义
- [ ] INV-22 权限隔离：非本人订单/权益访问返回 FORBIDDEN 且无副作用

**积分与礼物**

- [ ] INV-11/12 余额安全 + 同事务账本：余额永不为负；每笔变动有 `balance_after`
- [ ] INV-13/14 账本是唯一事实来源且不可变：`balance == Σ delta`；历史无 UPDATE/DELETE
- [ ] INV-15 结构化幂等键：一单多项事件入账不互相顶掉；事件驱动条目 `ref` 非空；单列 `ref_id` 唯一判定为不符合
- [ ] C2 原子扣减：并发扣减不超扣（见 T-26）
- [ ] OP-N1/N2 幂等：同一键重复入账只生效一次
- [ ] OP-N5 积分兑换：扣分与订单转 paid 同事务；余额不足无副作用
- [ ] INV-18/19 事件原子与幂等消费：重复投递不重复发放
- [ ] 限量礼物并发购买不超卖（Gifts 等级）

**周边与对账**

- [ ] OP-O1 实体商品必须校验地址归属（Physical 等级）
- [ ] OP-S1 发货幂等；发货单含地址快照
- [ ] INV-23 可对账：未匹配结算与失败事件可查询
- [ ] INV-24 审计：权益/积分/礼物/退款变更均有 actor + reason
- [ ] INV-25 失败可重放：手动重放历史事件不破坏不变量

**争议 / 发票 / 多币种（v0.3）**

- [ ] Dispute 状态机封闭 + 冻结范围（INV-29，T-44~T-46）
- [ ] 发票快照不可变 + 红冲不改原票（T-47/T-48）
- [ ] 跨币种快照汇率 + 原币退款（INV-30，T-49/T-50）

## 3. 设计判据清单（五个老师傅测试，D-1~D-5）

> 跨等级必检。判据出处与原文见 [../master-craft.md](../master-craft.md) §3。
> 这五条与 §4 的测试向量**不互相替代**：测试向量是"验收脚本"，设计判据是"设计审查"——
> 即使 T-01~T-50 全绿，这五条任一不过，仍判定不符合（例如：余额表可直接删除且账本不存在）。

| # | 判据 | 必检问题 | 通过证据（写进符合性报告） |
| --- | --- | --- | --- |
| D-1 删表重建 | 派生结构可删可重建 | 删掉余额、计数器、索引、缓存等派生结构后，钱与权益事实仍完整存在于账本/事件日志，且能由其重建 | 重建步骤 + 重建前后 `balance == Σ delta` 输出 |
| D-2 一年后审计 | 每个数都能回溯 | 抽查任意一笔入账/退款/发放，"为什么是这个数"能指向一条不可变记录（分录/快照/事件，含 actor + reason + occurred_at） | 至少 1 笔退款 + 1 笔赠送的完整审计链 |
| D-3 并发同发 | 竞争恰好一个赢 | 两个语义相同的请求同时到达：恰好一个成功，失败方得到明确、可解释的错误，无部分副作用 | 并发压测输出（如 T-26 的 10 并发扣减） |
| D-4 事件重放 | 重放逐字节一致 | 同一条事件重放两次：到期时间、余额、发放事实条数等可观测状态逐字节一致 | 重放脚本 + 两次重放前后 diff |
| D-5 回滚演练 | 新版本可退回 | 部署新版本发现问题后可退回旧版本：旧版本能读新版本写的数据、迁移可逆或安全降级 | 回滚步骤 + 回滚后冒烟通过输出 |

## 5. 判定规则

1. 声明范围内的 **MUST 清单全部通过**，且**五条设计判据（§3 D-1~D-5）全部通过** →
   判定为"**MSP 符合（等级 X）**"，系统可用；
2. 任一 MUST 或设计判据未通过 → **不符合**：MUST 可修复或降低声明等级；设计判据是跨等级底线，
   **不得**通过降低声明等级豁免（不得静默忽略）；
3. SHOULD 未通过 → 记录为已知偏差，并在报告中给出风险说明与后续计划；
4. 判定必须有**可复现证据**：测试命令、期望值、实际输出、时间戳。

```markdown
# MSP 符合性报告
- 实现：<项目名/版本>  时间：<UTC>  范围：Core + Subscriptions + Points
- 环境：<数据库/队列/支付渠道，附版本>

| 用例 | 结果 | 证据 |
| --- | --- | --- |
| T-02 | ✅ | `bash scripts/smoke.sh` 输出见附录 A |
| T-03 | ✅ | `bash scripts/smoke-idempotency.sh` 输出见附录 B |

结论：MUST 36/36 通过，SHOULD 1 项偏差 → **符合 Core + Subscriptions + Points**。
```

## 7. 反模式（出现即判定不符合）

- 用单测/编译通过替代端到端验收；
- 只在 happy path 验证，未覆盖"重复投递 / 重复点击 / 重复退款"；
- 从订单或支付状态推断访问权；
- 退款只改订单状态而不回退权益与余额；
- 余额或库存直接 `UPDATE` 而无账本；
- 事件消费者不做幂等去重；
- 事件重试导致权益重复顺延（发放/续期没有按 source 幂等）；
- 金额指纹的尾数计入退款金额。
